# 뒤쪽 내용을 추가하는 기준

장면마다 고유 ID를 쓰고 sourceNumber는 원본 24장 대응에만 사용합니다. 후속 장면은 별도 chapter로 추가합니다.
대사·정답·힌트·배경·표정·미니게임 링크는 데이터로 수정합니다. UI 엔진 안에 긴 대사를 하드코딩하지 않습니다.
새 장면을 삽입해도 ID로 저장한 기존 진행 위치를 복구할 수 있어야 합니다.

## 후속 코스의 기본 순서

장소 이동 확인(예/아니오) → 짧은 공간 소개 → 고양이의 사고 → 현장 문제 → 미니게임 → 다음 장소.
모든 장소에 엽서나 미니게임을 강제로 넣지 않습니다.

## 미니게임 연결

메인 화면의 중앙에는 게임 시작 버튼, 하단에는 클리어 키워드 입력칸과 확인 버튼을 둡니다.
같은 탭 안에서 미니게임을 크게 띄우며, 메인이 관리하는 바깥 영역의 상단에 ‘이야기로 돌아가기’를 항상 표시합니다.
미니게임 성공 화면에서 키워드를 확인한 뒤 돌아와 입력합니다. 키워드가 맞아야 다음 스토리로 진행합니다.
돌아오기만으로 정답 처리하지 않습니다. 이미 푼 현장 문제와 현재 단계는 유지합니다.
다른 출처의 게임 페이지 성공 결과를 자동으로 읽을 수 있다고 가정하지 않습니다. 자동 클리어 연동은 이 프로젝트의 진행 조건이 아닙니다.

책 받기 키워드 ‘뿌듯’은 예시입니다. 최종 키워드로 임의 확정하지 않습니다.
이번 24장에는 미니게임 장면이 없으므로 뒤쪽 3~5개 게임을 한꺼번에 새로 제작하지 않습니다.
최초 추가 테스트가 필요하면 제작자 전용 메뉴에서 미니게임 한 개만 연결하고, 실제 클리어 화면에 키워드를 넣는 작업이 필요한지 확인합니다.

## 마지막

엽서 홍보면 오른쪽 위와 왼쪽 아래 노란 부분을 반대 면으로 접으면 두 캐릭터 머리가 만나며 최종 문장이 완성됩니다.
정답 ‘고양이와 사서가 돌아왔다’ 이후의 계단 충돌과 몸 되돌리기는 자동 연출입니다. 추가 키워드나 실패 조건을 만들지 않습니다.
